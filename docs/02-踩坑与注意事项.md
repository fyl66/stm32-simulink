# 踩坑与注意事项（STM32 + Simulink）

按"现象 → 原因 → 解决/抑制"记录。均为本仓库实测遇到并解决的问题。

---

## 1. 授权功能名陷阱

**现象**：`license('test','Simulink_Coder')`、`license('test','Embedded_Coder')` 返回 0，构建报
`codertarget:build:NonAuthorizedSLTarget`："MATLAB Coder, Simulink Coder and Embedded Coder products are required…"。

**原因**：这两个是**产品名**，不是**许可功能名**。真实功能名为 `real-time_workshop`（Simulink Coder）与 `rtw_embedded_coder`（Embedded Coder）。

**解决/核对**：

```matlab
bc = matlab.internal.product.getBaseCodeFromProductName('Embedded Coder');
fi = matlab.internal.licensing.getFeatureInfo(bc);
license('test', fi.feature)   % rtw_embedded_coder
```

**结论**：授权核查一律用 `getFeatureInfo(...).feature`，不要用产品名。

## 2. 中文 / 空格路径（最隐蔽）

**现象**：编译阶段 `fatal error: main.h: No such file or directory`；日志里中文变乱码（`桌面`→`妗岄`），`.mk` 里出现 `????`。

**原因**：GNU 工具链 / make 对非 ASCII 路径编码不兼容。

**解决**：工程放在**纯 ASCII 路径**（本仓库为 `E:\stm32_simulink`）。
迁移后需更新模型内路径：

```matlab
run('E:\stm32_simulink\scripts\stm32_update_paths.m')   % 更新 STM32CubeMX.ProjectFile
```

**抑制**：`.gitignore` 中不要出现中文路径；脚本一律用相对自身定位。

---

## 3. 时基源必须是 TIM2（不能是 SysTick）

**现象**：`stm32:codegen:STM32CubeMXTimebaseSourceSystick`。

**原因**：Blockset 用 SysTick 调度任务，要求 CubeMX 的 SYS Timebase Source 换成其它定时器。

**解决**：`.ioc` 中把 `VP_SYS_VS_Systick` 改为 `VP_SYS_VS_tim2`，并加：

```text
NVIC.TIM2_IRQn=true\:15\:0\:false\:false\:true\:false\:true\:true
NVIC.TimeBase=TIM2_IRQn
NVIC.TimeBaseIP=TIM2
```

---

## 4. 设备检测 `No STM32 MCU connected`

**现象**：编译链接成功，烧录前报
`The following error occurred during deployment to your hardware board: No STM32 MCU connected.`

**原因（两层）**：
1. 程序化设置 `STM32CubeMX.ProjectFile` 后，模型里的 `STM32CubeMX.DeviceId` 仍是占位符 `<Select STM32CubeMX project>`。
2. CubeProgrammer ≥ 2.20 报**分组设备名**（如 `STM32F101/F102/F103 Medium-density`），而 Blockset 的匹配逻辑期望**具体料号**（如 `STM32F103C8Tx`）。

**解决**：
```matlab
codertarget.data.setParameterValue(m,'STM32CubeMX.DeviceId','STM32F103C8Tx');
codertarget.data.setParameterValue(m,'STM32CubeMX.Family','STM32F1');
```
并对设备名匹配打补丁（见第 5 条）。

## 5. CubeProgrammer 版本兼容补丁

**现象**：即使 `DeviceId` 正确，设备列表仍为空。

**原因**：`stm32cube.parameters.internal.getConnectedDevicesList` 用 `contains(DeviceId, dName)` 过滤，`dName` 由 CubeProgrammer 输出的设备名拆分而来；2.23 的分组名无法匹配。

**解决**：补丁 `getConnectedDevicesList.m`，兼容分组名（详见 `docs/patches/getConnectedDevicesList-2.23.patch.md`）。
由于 MATLAB 优先使用同名 `.p`，需把 `.p` 备份改名，让 `.m` 生效，并刷新缓存：

```matlab
rehash toolboxcache; rehash path;
```

**更"正统"的替代**：安装 Blockset 推荐的 **STM32CubeProgrammer 2.17.0**，则无需补丁。
**回退**：见补丁文档。

## 6. CMSIS / CMSIS-DSP / CMSIS-NN 未安装或未注册

**现象**：`stm32:codegen:NoRequiredToolsInstalled`：
"CMSIS, CMSIS-DSP tool is not installed or registered…"。

**原因**：`C:\ProgramData\MATLAB\...\cmsis\...` 下有文件但**未注册**；DSP/NN 常缺失。

**解决**：`scripts/stm32_install_cmsis.m`（`shared3pcmsis.download/install/register3pCMSISFolder`）。
验证：`shared3pcmsis.get3pCMSISInstallFolder('cmsis_dsp')` 非空。

---

## 7. 固件包被装到 C 盘仓库

**现象**：`getSTM32CubeFirmwarePackageDetails('F1')` 找不到包，但 CubeMX 明明下载成功。

**原因**：`swmgr install` 使用 CubeMX 自己的 `updater.ini` 中的 `RepositoryPath`（默认 C 盘），与 MATLAB 首选项里的仓库不同。

**解决**：迁移固件目录到目标仓库，并修改
`C:\Users\<user>\.stm32cubemx\plugins\updater\updater.ini` 的 `RepositoryPath`。

---

## 8. 非交互构建被 `questdlg` 阻塞

**现象**：`matlab -batch` 下 `slbuild` 报
`MATLAB:hg:NonInteractiveFunctionSupport`（`codertarget.target.configureModelIfRequired` 调用了 `questdlg`）。

**原因**：无头模式不支持阻塞式对话框。

**解决**：仅在无头构建期间，在工程目录临时放一个自动应答的 `questdlg.m`，构建后**删除**（已加入 `.gitignore`）。
模型配置完成后，正常构建不会再触发该对话框。

---

## 9. CubeMX 版本偏新（6.18.1-RC2）

**现象**：注册时告警"检测到 6.18.1，推荐 6.12.0…可能引入不兼容"。

**说明**：本次实测可用。但 Blockset 源码中有 `6.12.0` 专用分支，且 RC 版本风险高。

**回退**：若代码生成阶段报错，安装 **STM32CubeMX 6.12.0** 到独立目录并重新 `updateSTM32CubeMXPath`。

---

## 10. 硬件注意

- LED 等外设必须串限流电阻（330Ω~1kΩ），避免超过 GPIO 灌电流。
- 确认板上有 8MHz HSE 晶振；无晶振则改用 HSI。
- ST-LINK 需能识别目标：`STM32_Programmer_CLI -c port=SWD` 应打印 `Device name`。

---

## 11. 其他

- 构建目录含空格时 Simulink 会告警（MATLAB 安装在 `Program Files`）；本仓库工程路径无空格，可忽略。
- 若 `which` 仍指向已改名的 `.p`，执行 `rehash toolboxcache`。
- 首次下载固件/CMSIS 需联网；CubeMX 下载固件可能要求 **myST 登录**。
